# @fire/backend — Convex backend (read-only copy)

> **This folder is a copy. Do not deploy from it.**
> The deploy source of truth is Coco's Convex project (`/workspace/convex-project` on the agent box),
> which is deployed to `elegant-echidna-735`. Running `npx convex dev` or `npx convex deploy` from
> here would overwrite Coco's deployed functions with whatever is in this copy.

Why it's here: the web app (and later the mobile app) imports the generated, fully-typed API from
`convex/_generated/api` so every `useQuery` / `useMutation` call is type-checked against the real
backend.

- `convex/` — schema, queries, mutations, actions, HTTP routes (copied without `.env*`,
  `node_modules` or the scratch `zzTest.ts`).
- `API.md`, `SCHEMA.md` — reference docs generated by Coco.
- `scripts/` — Coco's backend smoke scripts (they read the deployment URL from the environment).

## Keeping it in sync

When Coco changes the backend, refresh this copy (from the agent box or wherever you have Coco's project):

```bash
rsync -a --delete --exclude node_modules --exclude '.env*' --exclude convex/zzTest.ts \
  /workspace/convex-project/ packages/backend/
# keep this README and package.json
git checkout -- packages/backend/README.md packages/backend/package.json
npm run typecheck   # catches web code that no longer matches the API
```

`convex/_generated` must be included — it is what the web app's types come from.
